# 증빙 기반 평판 시스템

> 별점 하나가 학생의 커리어를 결정하지 않도록 합니다.

학생 평판은 단순 평균 대신 Bayesian 보정, 평가자 신뢰도, 프로젝트 증빙 일치도와 이상치 탐지를 함께 사용한다. 리뷰 원점수와 원문은 보존하며, 보정값은 종합 평판과 협업 온도 계산에만 사용한다.

## 처리 흐름

1. 의뢰인이 만족도·기한·소통·인수인계·결과물 품질을 평가한다.
2. 제출 버전, 완료 조건, 기한, 결과물 수령과 실제 사용 기록을 평가와 비교한다.
3. 평가자의 과거 점수 편향으로 내부 신뢰도를 계산한다.
4. 내부 항목 또는 증빙과 충돌하는 평가는 `FLAGGED`로 보류한다.
5. 정상 평가만 가중한 뒤 Bayesian Average를 적용한다.
6. 검증 프로젝트 수·완료율·기한·인수인계·소통 지표와 결합해 100점 평판을 계산한다.
7. 학생이 이의를 제기하면 `DISPUTED`로 바꾸고 확정 전까지 집계에서 제외한다.

상태 흐름은 `NORMAL / FLAGGED → DISPUTED → UNDER_REVIEW → VALID / PARTIALLY_VALID / INVALID`이다. MVP는 자동 탐지와 학생 이의제기까지 제공하며, 최종 운영 판정 상태를 저장할 DB 구조를 포함한다.

정책값은 `supabase/functions/_shared/portfolio/reputationPolicy.ts`에서 관리한다. 평판 변경 사유는 `reputation_events`, 이의제기는 `review_disputes`에 기록한다.

## 평판 구성

- Bayesian 리뷰 점수: 40%
- 검증 프로젝트 완료율: 25%
- 기한 준수: 15%
- 인수인계: 10%
- 소통: 10%

조회수나 매출 증가는 학생이 통제하기 어려우므로 평판 점수에 직접 넣지 않는다. 정당한 낮은 평가는 프로젝트 실패 기록과 일치하면 정상 반영한다.
